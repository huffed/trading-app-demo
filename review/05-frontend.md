## 2. Misleading or missing displays (ranked)

**F1 — No account-level loss-limit view; per-algo gauges hide aggregate exposure. Critical.**
Five algos share one $100K account, but every FTMO gauge is computed per `algorithm_id` (`ftmo-compliance-actions.ts:117-135`) against the full `capital` (`:62-65`). Two sibling-identical trades on 08-31 and 09-03 (lead §6) each showed 0.42% on two separate cards; the account lost 0.84%. Worst case under current rules (2 losses/algo/day × 5 algos, plus observed stop slippage) approaches the 5% limit while every card says "OK". No portfolio gauge exists on the dashboard (`src/app/(dashboard)/dashboard/page.tsx:11-25`). The daily gauge also uses UTC midnight and a fixed-capital denominator where FTMO uses 00:00 CE(S)T and the day-start balance (`ftmo-compliance-actions.ts:62-66,115`; countdown `ftmo-compliance-card.tsx:27-54`), and it labels the 80% internal halt level as the threshold (`:85-86`, rendered `ftmo-compliance-card.tsx:73-75`). On any query failure the hook returns `null` and the card unmounts (`src/hooks/use-ftmo-compliance.ts:17-20`; `ftmo-compliance-card.tsx:174`) — indistinguishable from "no prop_firm rule".

**F2 — The M1 gate statistic has survivorship bias. Critical.**
`buildM1Evidence` loads only `status='active'` algos (`m1-evidence.ts:134-141`) and then only positions belonging to them (`:154`). Pausing or archiving an algo — manually via the edit view, or automatically by the alpha-decay cron which writes `status:'paused'` (`src/lib/cohort/alpha-decay.ts:322`) — removes its (typically losing) trades from the portfolio mean R the gate is judged on. The unit test enshrines this (`src/lib/cohort/m1-evidence.test.ts:123-126`). The dashboard "Realized · M1" total uses a different window definition again (`closed_at ≥ clock_start`, `paper-trading-actions.ts:385-394`; M1 uses `opened_at`, `m1-evidence.ts:155`).

**F3 — M1 verdict shown from trade 1 with no uncertainty; "complete-fidelity" label. High.**
`in_band` is non-null from the first closed trade (`m1-evidence.ts:272-275`) and the UI renders a red "Accruing — outside band" badge (`m1-tab.tsx:79-82`), softened only by a grey hint (`:91`). No standard error, CI or power is shown anywhere in the tab (`m1-tab.tsx:97-156`); the lead derived SE ≈ 0.25–0.29R at n=30 against a half-width of 0.0765R (~22% power). The footer calls the baseline a "pinned-corpus complete-fidelity harness" (`m1-tab.tsx:62-63`; `m1-baseline.ts:9,65-66`) while the lead documented a $10K-pool lot floor, a daily-bias staleness gap and a quote-vs-bar fill model. The tab's fill caveat (`m1-tab.tsx:27-28`) contradicts the builder's own header, which claims friction is excluded on both sides while admitting the baseline is friction-inclusive (`m1-evidence.ts:16-19`). `n={843}` is a JSX literal (`m1-tab.tsx:62`), not `M1_BASELINE.portfolio.n` (`m1-baseline.ts:71`); the clock-start label "since 20 Jul" is also a literal (`live-status-rail.tsx:96`). Evidence rows show relative times ("2mo ago") not timestamps (`m1-tab.tsx:243-244`) and raw `exit_reason` (`:255`).

**F4 — Query failures render as a healthy, empty dashboard. Critical.**
None of the dashboard panels check `isError`: KPI strip falls back to `0`/"no scans yet" (`src/components/dashboard/kpi-summary.tsx:69,83,97-98`), rail shows "Active algorithms 0 / Last scan never / +$0.00" (`live-status-rail.tsx:82-102`) and "no ticks yet" when the heartbeat RPC fails (`:40`), positions panel says "No open paper positions." (`open-positions-panel.tsx:60-61`), activity says "No activity yet — start a scan" (`src/components/dashboard/activity-panel.tsx:79-82`), hero says "Need at least 2 closed paper trades" (`src/components/dashboard/equity-hero.tsx:108-112`). A PostgREST/RLS/network failure therefore hides open positions and any limit state behind reassuring copy. (The Oct 13–19 lockout probably also broke auth → login redirect; partial failures do not.) The `/reports` tabs do render errors (`m1-tab.tsx:41-53` etc.) — the dashboard should match.

**F5 — "Cron heartbeat" monitors manage only; scan death is invisible in the UI. High.**
`useHeartbeat` calls only `last_manage_tick` (`use-heartbeat.ts:22`); `last_scan_tick` is unused in `src/` outside the cron route. The dead-man workflow checks both; the UI label implies one combined heartbeat (`live-status-rail.tsx:74`). Staleness is colour-only (`:53-56`). The hook comment still says "the local Mac cron is dead" (`use-heartbeat.ts:6-8`); production is a VPS.

**F6 — Stale data looks live; silent daily-bar fallback is written to the DB. High.**
While the dashboard or an algo page is open with open positions, `useAutoRefreshPrices` calls `refreshPositionPrices` every 60 s (`src/hooks/use-paper-trading.ts:223-250`), which writes `current_price`/`unrealized_pnl` (`paper-trading-actions.ts:285-289`) from Twelve Data or, on any failure, the **last cached daily close** (`:303-342`) — no timestamp or provider is stored or shown (`open-positions-panel.tsx:68-70`). The manual "Close position" dialog promises "current market price" (`src/components/algorithms/position-cards.tsx:48`) but the action prices the fill from `getCachedPrices(ticker, "compact")`, i.e. the last daily bar (`paper-trading-actions.ts:172-179`), then records it as `exit_price`/`realized_pnl` (`:189-199`) — a manual close enters M1 evidence at a price that can be a day old. The position quote action carries `fetched_at` (`src/app/(dashboard)/algorithms/position-stats-actions.ts:20,74`) but the panel never renders it (`position-stats-panel.tsx:71-81`); the chart's live-price action returns `ts` (`src/app/(dashboard)/chart/actions.ts:232-236`) and the page drops it (`chart/page.tsx:96`).
